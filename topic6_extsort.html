Εξωτερική Ταξινόμηση

Πώς ταξινομείς ένα αρχείο N σελίδων με μόνο B πλαίσια μνήμης: runs, συγχωνεύσεις B−1 δρόμων, ο τύπος του κόστους, double buffering, replacement sort (runs ≈ 2B) και πότε ένα B+ δέντρο κάνει τη δουλειά για σένα.

Η Ουσία σε 60 δευτερόλεπτα

ΤΙ ΚΑΝΕΙ
Όταν τα δεδομένα δεν χωράνε στη μνήμη: (1) κόψε το αρχείο σε κομμάτια που χωράνε, ταξινόμησέ τα στη μνήμη και γράψ' τα πίσω ως ταξινομημένα runs· (2) συγχώνευσε πολλά runs ταυτόχρονα (όσα επιτρέπουν τα πλαίσια) σε μεγαλύτερα, ξανά και ξανά, μέχρι να μείνει ένα. Κάθε πέρασμα διαβάζει και γράφει όλο το αρχείο: 2N I/O ανά πέρασμα.

Διαίσθηση: ταξινόμηση 1.000 γραπτών με γραφείο που χωρά 10: φτιάχνεις 100 ταξινομημένες στοίβες των 10· μετά παίρνεις 9 στοίβες μαζί, κοιτάς τα «πάνω» γραπτά και βγάζεις κάθε φορά το μικρότερο σε νέα στοίβα (το 10ο σημείο του γραφείου είναι η έξοδος). Όσο μεγαλύτερο γραφείο, τόσο λιγότερα «γύρα».

✅ Λιγότερα περάσματα όταν…
  • μεγαλώνει το B (λογαριθμική βάση B−1)
  • τα αρχικά runs είναι μακρύτερα (replacement sort ≈ 2B)
  • υπάρχει clustered B+ στο κλειδί
❌ Ακριβό όταν…
  • B = 3 (2-way) σε τεράστιο N
  • χρησιμοποιείς unclustered B+ για ταξινόμηση (ίδιο μπλοκ ξανά και ξανά)
  • αφήνεις την εικονική μνήμη να κάνει «εσωτερική» ταξινόμηση
📝
Για τις εξετάσεις θυμήσου: (1) Πέρασμα 0: ⌈N/B⌉ runs των B σελίδων. (2) Κάθε επόμενο πέρασμα συγχωνεύει B−1 runs (1 πλαίσιο έξοδος). (3) #περάσματα = 1 + ⌈logB−1⌈N/B⌉⌉, κόστος = 2N · #περάσματα. (4) Replacement sort: B−2 current set, 1 input, 1 output, μέσο μήκος run ≈ 2B.
❓

1. Γιατί Ταξινόμηση;

  • Δεδομένα ζητούνται σε σειρά (ORDER BY).
  • Bulk loading ευρετηρίων (B+) — Topic 5.
  • Απαλοιφή διπλοτύπων.
  • GROUP BY.
  • Απαραίτητη για τη Sort-Merge ζεύξη.
Το βασικό ερώτημα

Τι γίνεται αν τα δεδομένα δεν χωράνε στη μνήμη; Να αφήσουμε την εικονική μνήμη να κάνει μια «εσωτερική» ταξινόμηση (π.χ. heap-sort); Όχι — οι τυχαίες προσπελάσεις θα γίνουν page faults/I/O. Χρησιμοποιούμε διαίρει και βασίλευε με «runs» σε φάσεις, με τα διαθέσιμα buffers.

2. 2-Way Merge Sort

  • Φάση 0 με 1 buffer: κάθε μπλοκ διαβάζεται, ταξινομείται, γράφεται πίσω → κάθε σελίδα γίνεται ένα run.
  • Φάση 1, 2, … με τουλάχιστον 3 buffers: 2 για είσοδο (ένα από κάθε run) + 1 για έξοδο· συγχωνεύονται ζεύγη runs → runs διπλάσιου μεγέθους.
  • Κάθε φάση: 1 πλήρης ανάγνωση + 1 πλήρης εγγραφή = 2N I/O.

⚠️ Προσοχή στον τύπο της διαφάνειας
Η διαφάνεια γράφει «#περάσματα = ⌈log₂(N/2)⌉» και «κόστος 2N·⌈log₂(N/2)⌉». Το δικό της σχήμα όμως (N=7) έχει 4 περάσματα, που δίνει ο κλασικός τύπος 1 + ⌈log₂N⌉ (πέρασμα 0 + ⌈log₂N⌉ συγχωνεύσεις). Στο γραπτό γράψε τον κλασικό τύπο και εξήγησε τι μετράς (π.χ. «πέρασμα 0 + 3 φάσεις συγχώνευσης»).

3. Γενικευμένη External Merge Sort (B πλαίσια)

Γενίκευση: αν έχουμε B−1 buffers για είσοδο και 1 για έξοδο, συγχωνεύουμε B−1 runs μαζί.

  • Πέρασμα 0: με όλα τα B buffers κάθε φορά → ⌈N/B⌉ αρχικά ταξινομημένα runs (μήκους B σελίδων).
  • Περάσματα 1, 2, …: B−1 είσοδοι + 1 έξοδος → συγχώνευση B−1 runs.
#περάσματα = 1 + ⌈logB−1⌈N/B⌉⌉
κόστος = 2·N·(#περάσματα)

Η διαφάνεια γράφει ⌈N/(B−1)⌉ για τα runs του περάσματος 0· ο πίνακας της επόμενης διαφάνειας όμως ταιριάζει ακριβώς με ⌈N/B⌉ (π.χ. N=10.000, B=3 → 13). Συνήθως βγαίνει το ίδιο αποτέλεσμα· ο simulator δείχνει και τα δύο.

Κάθε μπλοκ έχει έως 2 εγγραφές· 1 buffer κρατιέται για τα ενδιάμεσα αποτελέσματα (έξοδο). Καθώς τα μπλοκ είναι στη μνήμη, επιλέγεται κάθε φορά το μικρότερο κλειδί για τη δημιουργία των runs. Ο αριθμός B των πλαισίων είναι κρίσιμος: όσο αυξάνει, τόσο μεγαλύτερα τα οφέλη.

5. Double Buffering

Ιδέα: δέσμευσε «σκιώδη» (shadow) input/output buffers. Ενώ η CPU συγχωνεύει από το ένα σετ buffers, ο δίσκος γεμίζει/αδειάζει το άλλο → πολυπλεξία CPU και I/O και μικρότερος συνολικός χρόνος απόκρισης (turnaround). Κόστος: διπλάσιος χώρος ανά ρεύμα → λιγότερα runs συγχωνεύονται ανά πέρασμα (μικρότερο fan-in), αλλά δεν περιμένουμε ποτέ τον δίσκο.

6. Replacement Sort — Μακρύτερα Runs

Στόχος: μεγαλύτερα αρχικά runs → λιγότερα runs → λιγότερες φάσεις συγχώνευσης. Το Πέρασμα 0 είναι εντελώς διαφορετικό από το κλασικό.

Κατανομή των B buffers
  1. B−2 = current set (κρατά R εγγραφές)
  2. 1 input buffer
  3. 1 output buffer

Αρχικά φορτώνονται τα πρώτα B−2 μπλοκ στο current set και το επόμενο στο input.

Αλγόριθμος
  1. Οι εγγραφές του input μπαίνουν στις θέσεις του current set που άδειασαν (έφυγαν προς την έξοδο).
  2. Όταν το input αδειάσει, διαβάζεται το επόμενο μπλοκ.
  3. Μια εγγραφή μπαίνει στο output μόνο αν το κλειδί της είναι ≥ l, το μεγαλύτερο κλειδί που έχει βγει ως τώρα (συνθήκη).
  4. Το run τελειώνει όταν κανένα κλειδί του current set δεν πληροί τη συνθήκη.
Παράδειγμα διαφάνειας (M = 7: 1 input, 1 output, 5 current set, 2 εγγραφές/μπλοκ)

Το run που σχηματίζεται έχει ήδη γράψει τα μπλοκ [14,16], [17,20], [21,22] με l = 22, και συνεχίζει με [23,25] (l = 25) … Κλειδιά μικρότερα από l που μπαίνουν από το input (π.χ. 12, 13, 17, 18, 19) «περιμένουν» για το επόμενο run.

7. Ταξινόμηση με B+ Δέντρο

Αν ο πίνακας έχει ήδη B+ ευρετήριο στις στήλες ταξινόμησης: γιατί να μη διασχίσουμε τα φύλλα με τη σειρά;

Case I: Clustered → δουλεύει καλά
  • A1: ρίζα → αριστερότερο φύλλο, μετά διάσχιση όλων των φύλλων (οι εγγραφές είναι εκεί).
  • A2: ίδια διάσχιση, αλλά για κάθε μπλοκ δεδομένων ένα I/O — επειδή είναι clustered, κάθε μπλοκ διαβάζεται περίπου μία φορά.
Case II: Unclustered (A3) → όχι καλά
  • Τα φύλλα έχουν κλειδιά + recIDs σε σκόρπια μπλοκ.
  • Διασχίζοντας με αύξουσα σειρά, το ίδιο μπλοκ μπορεί να ζητηθεί πολλές φορές → έως ένα I/O ανά εγγραφή → συχνά χειρότερο από external sort.
