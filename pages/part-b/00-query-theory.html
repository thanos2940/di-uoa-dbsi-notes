Βασικοί Τελεστές & Σχεσιακή Άλγεβρα

Εισαγωγή: Από SQL σε Φυσικά Πλάνα

Όταν γράφουμε ένα ερώτημα SQL, όπως SELECT name FROM Students WHERE gpa > 3.5;, το DBMS δεν το εκτελεί απευθείας.

  1. Το μεταφράζει σε Σχεσιακή Άλγεβρα: \(\pi_{name}(\sigma_{gpa>3.5}(Students))\)
  2. Ο Query Optimizer επιλέγει τους κατάλληλους Φυσικούς Αλγορίθμους (π.χ. Index Scan vs Table Scan).

1. Σχεσιακή Άλγεβρα (Relational Algebra)

Επιλογή (Selection - \(\sigma\))

Φιλτράρισμα γραμμών με βάση συνθήκη.

$$\sigma_{condition}(R)$$

Παράδειγμα: SELECT * FROM Students WHERE age > 20

Προβολή (Projection - \(\pi\))

Επιλογή στηλών (και αφαίρεση με distinct).

$$\pi_{A_1, A_2}(R)$$

Παράδειγμα: SELECT DISTINCT name FROM Students

Ζεύξη (Join - \(\bowtie\))

Συνδυασμός πινάκων.

$$R \bowtie_{R.A=S.B} S$$

Παράδειγμα: FROM R, S WHERE R.A = S.B

Αλγεβρικές Ιδιότητες (SOS για Σωστό/Λάθος)

  • Αντιμεταθετικότητα: \(R \bowtie S = S \bowtie R\)
  • Προσεταιριστικότητα: \((R \bowtie S) \bowtie T = R \bowtie (S \bowtie T)\)
  • Διαφορά: \(R - S \neq S - R\)
Push-down Selections: Είναι καλύτερο να φιλτράρουμε τα δεδομένα πριν τη ζεύξη!
\(\sigma_{\theta}(R \bowtie S) \rightarrow \sigma_{\theta}(R) \bowtie S\) (αν το \(\theta\) αφορά μόνο το \(R\))

2. Φυσικοί Τελεστές & Κόστος

Table Scan vs Index Scan

Λειτουργία Clustered Index Non-Clustered Index Table Scan (No Index)
Equality (A=c) \(d(I) + \lceil \frac{p(R)}{V(A,R)} \rceil\) \(d(I) + \lceil \frac{t(R)}{V(A,R)} \rceil\) \(p(R)\)
Range (A>c) \(d(I) + fraction \cdot p(R)\) Συνήθως Χειρότερο από Scan! \(p(R)\)
Σημείωση:
  • \(p(R)\): Αριθμός σελίδων (blocks).
  • \(t(R)\): Αριθμός εγγραφών (tuples).
  • \(V(A,R)\): Πλήθος διακριτών τιμών (διαφορετικών) στο πεδίο A.
  • \(d(I)\): Βάθος δέντρου ευρετηρίου.

3. Solved Example: Υπολογισμός Κόστους

Άσκηση Κόστους

Δεδομένα:

  • Πίνακας Students με \(p(R) = 500\) σελίδες, \(t(R) = 50,000\) εγγραφές.
  • Πεδίο department με \(V = 10\) διαφορετικές τιμές.
  • Query: SELECT * FROM Students WHERE department = 'CS'

Ζητείται: Σύγκριση κόστους μεταξύ Table Scan και Ευρετηρίων.

Λύση:

1. Table Scan (χωρίς ευρετήριο):

Διαβάζουμε όλο το αρχείο.

Cost = p(R) = 500 I/Os
2. Clustered Index (βάθος 3):

Οι εγγραφές είναι ταξινομημένες (συνεχόμενες σελίδες).

Selectivity = \(1/10\). Άρα διαβάζουμε το 1/10 των σελίδων.

Cost = 3 + (500 / 10) = 3 + 50 = 53 I/Os
3. Non-Clustered Index (βάθος 3):

Οι εγγραφές είναι διάσπαρτες. Κάθε match μπορεί να είναι σε άλλη σελίδα!

Matches = \(50,000 / 10 = 5,000\) εγγραφές.

Cost = 3 + 5,000 = 5,003 I/Os

Πολύ χειρότερο από το Table Scan (500)!

Συνοψίζοντας
Όταν η "επιλεκτικότητα" (selectivity) είναι μικρή (λίγες εγγραφές), το Index συμφέρει. Αν ζητάμε μεγάλο μέρος του αρχείου (π.χ. > 10%), το Table Scan είναι συχνά καλύτερο από Non-Clustered Index!
