ΣΔΒΔ & Αποθήκευση

Πού κάθεται το ΣΔΒΔ, γιατί το κόστος μετριέται σε I/O, πώς δουλεύει ένας μαγνητικός δίσκος (seek + περιστροφή + μεταφορά), τι αλλάζει με τα SSD (NAND, write amplification, FTL), τριτογενής αποθήκευση και RAID επίπεδα 0–6.

ΤΙ ΚΑΝΕΙ
Ένα ΣΔΒΔ κρατά TB δεδομένων στον δίσκο (μη πτητικό, φθηνό) και τα φέρνει σε σελίδες/μπλοκ στη RAM για επεξεργασία. Η «κίνηση» μπλοκ πάνω-κάτω στην ιεραρχία μνήμης είναι αυτό που κυριαρχεί στον χρόνο. Άρα όλο το μάθημα μετρά κόστος σε αριθμό I/O.

Διαίσθηση: ένας μαγνητικός δίσκος είναι σαν πικάπ: για να διαβάσεις, το χέρι πρέπει να πάει στο σωστό «αυλάκι» (seek — το πιο αργό), να περιμένει να έρθει η σωστή θέση από κάτω (περιστροφή) και μετά να διαβάσει (μεταφορά). Αν τα μπλοκ σου είναι το ένα δίπλα στο άλλο, πληρώνεις το seek μία φορά — αν είναι σκόρπια, κάθε φορά. Γι' αυτό τα 1000 μπλοκ θέλουν ~16 s τυχαία αλλά ~38 ms σειριακά!

✅ Καλό για τον δίσκο
  • σχετικές εγγραφές στο ίδιο μπλοκ / ίδιο κύλινδρο
  • σειριακή ανάγνωση, prefetching
  • buffering στη RAM, scheduling αιτήσεων
❌ Κακό
  • τυχαίες αναγνώσεις σκόρπιων μπλοκ (seek κάθε φορά)
  • στα SSD: μικρές τυχαίες εγγραφές → write amplification
  • πολλοί δίσκοι χωρίς πλεονασμό → MTTF/N
📝
Για τις εξετάσεις θυμήσου: (1) t = ts + tr + ttr, μέση περιστροφική = ½ περιστροφής, το seek κυριαρχεί. (2) SSD: ανάγνωση γρήγορη, εγγραφή ~10× πιο αργή, διαγραφή block ~100× · WAF = φυσικά γραμμένα / λογικά γραμμένα. (3) RAID αξιοποίηση χώρου = D/(D+C): RAID-1 50%, RAID-4/5 με D=4: 80%, RAID-6: 66%. (4) MTTF πίνακα N δίσκων ≈ MTTF/N· νέα parity = (παλιά ⊕ νέα δεδομένα) ⊕ παλιά parity.

Πτητική μνήμη

  • Κύρια μνήμη: 10–100s ns, έως 128–256 GB — μικρή για πραγματικές ΒΔ. Η χωρητικότητα διπλασιάζεται, το κόστος πέφτει.
Γιατί δίσκος για το ΣΔΒΔ
  • Η RAM για TBs είναι ακριβή και πτητική.
  • Τα δεδομένα σε σελίδες/μπλοκ πρέπει να έρθουν στη RAM: read I/O σε ελεύθερο frame· όταν εκτοπίζονται → write I/O.
  • Αυτή η «κίνηση» μπλοκ κυριαρχεί στις λειτουργίες → αποθήκευσε ώστε να ξοδεύεται ελάχιστος χρόνος σε I/O.

3. Μαγνητικοί Δίσκοι (HDD)

Δεδομένα σε μαγνητικούς δίσκους (platters) που περιστρέφονται συνεχώς με συγκεκριμένα rpm γύρω από άξονα/άτρακτο (spindle).

Ανατομία
  • Platter: δεδομένα και στις δύο επιφάνειες, μία κεφαλή (ακίδα) ανά επιφάνεια.
  • Τροχιά (track): ομόκεντρος δακτύλιος· οι εξωτερικές είναι μεγαλύτερες.
  • Κύλινδρος: όλες οι τροχιές στην ίδια απόσταση από τον άξονα, σε όλους τους δίσκους («χτένι» βραχιόνων).
  • Τομέας (sector): σταθερό μέγεθος, συνήθως 256/512 B.
  • Μπλοκ: 1+ τομείς· σταθερό μέγεθος· μονάδα εισόδου-εξόδου. Διαβάζεται, επεξεργάζεται και ξαναγράφεται επί τόπου.
  • Ο βραχίονας κινείται μέσα-έξω· ένας stepper-motor τοποθετεί τη συστοιχία κεφαλών· δεν διαβάζουν/γράφουν όλες ταυτόχρονα.

Πίνακας διάλεξης: διάβασμα = (1) αναζήτηση (SEEK) = κίνηση βραχίονα, (2) αναμονή/καθυστέρηση (LATENCY) = κίνηση δίσκου.

Λυμένο: WD Blue 4TB — 1.000 μπλοκ των 4 KB

3 platters, 6 κεφαλές, 1.5–2.5 MB/τροχιά. Μέση περιστροφική 5,56 ms (5.400 RPM: 60.000/5.400/2), μέσο seek 10,5 ms, ρυθμός 175 MB/s → ttr = 4KB/175MB/s ≈ 0,022 ms.

Τυχαία: 1.000 · (10,5 + 5,56 + 0,022) = 16.082 ms ≈ 16 s
Σειριακά: 10,5 + 5,56 + 1.000 · 0,022 = 38 ms
→ η εγγύτητα των μπλοκ στον δίσκο είναι καθοριστική (≈ 420×)
Τεχνικές κατασκευαστών
  • Track alignment: οι τομείς «0» όλων των τροχιών ευθυγραμμίζονται → λιγότερη περιστροφική αναμονή.
  • I/O scheduling στον δίσκο: μέθοδος ανελκυστήρα (elevator) ή shortest-positioned track next.
  • Zoning: οι εξωτερικές τροχιές έχουν περισσότερους τομείς/μπλοκ.
Τεχνικές για αποδοτική πρόσβαση
  • καλό scheduling αιτήσεων → λιγότερη μηχανική κίνηση
  • RAM ως προσωρινή αποθήκη (buffer)
  • clustering: σχετικά δεδομένα «κοντά»
  • prefetching: φέρε νωρίτερα ό,τι θα χρειαστεί
  • logs στον δίσκο για αλλαγές που πρόκειται να γίνουν — WAL (Write-Ahead Log)

5. Flash & SSD

NAND-flash (SSDs) & EEPROM: τα δεδομένα επιβιώνουν διακοπές ρεύματος. Μια θέση γράφεται μία φορά — πρέπει πρώτα να σβηστεί για να ξαναγραφτεί· οι κύκλοι erase/write είναι πολλοί αλλά πεπερασμένοι· η εγγραφή παίρνει µs, η διαγραφή είναι πιο αργή. Πίνακας διάλεξης: NAND (Not AND) ≡ μνήμη flash, 2Δ ή 3Δ, εξτρά DRAM.

Write Amplification (WAF)

WAF = Physical Data Written to NAND / Logical Data Written by host OS

  1. Το ΛΣ στέλνει write() μιας σελίδας 4 KB.
  2. Το SSD γράφει τα 4 KB σε νέα σελίδα και σημειώνει την παλιά ως άκυρη (out-of-place).
  3. Ο garbage collector για να ανακτήσει το block με την άκυρη σελίδα πρέπει να αντιγράψει όλες τις έγκυρες σελίδες (1–4 MB) σε καινούργιο block.
  4. Αποτέλεσμα: η εγγραφή 4 KB οδήγησε σε εγγραφή πολλών MB. Οι συνεχείς εγγραφές φθείρουν τα κελιά.

Το FTL (Flash Translation Layer) μετακινεί παλιές σελίδες «από τη μέση» για να σβήσει ένα block → write amplification.

LBA (4 KB) vs NAND-page (16 KB)

Το ΛΣ ζητά λογικά μπλοκ (LBA) 4/8 KB· οι NAND σελίδες είναι συχνά 16 KB. Ο controller:

  • k = 4 λογικά μπλοκ διαθέσιμα → γράφονται μαζί σε μία σελίδα 16 KB.
  • k < 4 → κρατιούνται στην SSD-cache για να μαζευτούν με επόμενες εγγραφές.
  • k = 1 με fsync() → γράφεται αμέσως, το υπόλοιπο της σελίδας zero-padding.
  • Πάντα + meta-data & ECC.

Διαδρομές εγγραφής & ανάγνωσης

Flush βρώμικης σελίδας (λόγω fsync(), msync() ή background daemon pdflush/wb): FS & block layer (~1–5 µs) → host driver, doorbell & PCIe DMA (~1–3 µs) → SSD DRAM buffer, FTL mapping (~0,3–2 µs) → NAND data registers → physical NAND program (~100–1.500 µs) → interrupt (~1–2 µs). Το φυσικό γράψιμο κυριαρχεί.

read(): NVMe driver → controller & FTL (DMA, εύρεση σελίδας) → φόρτωση ολόκληρης 16 KB σελίδας στους registers → επιλογή μόνο των ζητούμενων 4 KB με offset → ECC & DMA στη RAM → completion interrupt.

Λυμένο: Samsung 870 EVO (SATA3 ≈ 600 MB/s)
1.000 μπλοκ των 4 KB = 3,906 MB. Χωρίς seek/περιστροφή: tseq = 1000·4KB / 600MB/s = 6,51 ms (τυχαία λίγο παραπάνω). Σύγκρινε με 38 ms σειριακά / 16 s τυχαία στον HDD.

8. RAID — Redundant Arrays of Inexpensive Disks

Οι καθυστερήσεις του HDD δεν αποφεύγονται — αλλά το throughput βελτιώνεται με παραλληλισμό: πολλοί δίσκοι ταυτόχρονα «κρύβουν» το latency (ευκολότερο: αντίγραφα σε πολλούς δίσκους· ενισχύθηκε από τη μείωση κόστους των HDD).

Data striping

Stripe unit = byte, bit ή μπλοκ. Ο πίνακας (αρχείο) = λογική σειρά stripes, κατανεμημένα round-robin:

D004812
D115913
D2261014
D3371115

Ο RAID ανακτά D μπλοκ τη φορά (D=4).

Αξιοπιστία

Ανεξάρτητες βλάβες: MTTF δίσκου 50.000 h (~6 χρόνια) → πίνακας 100 δίσκων: 50.000/100 = 500 h! Λύση: check disks με πληροφορία υγείας για τους D δίσκους.

Parity με 1 check disk: για κάθε θέση bit, μέτρα πόσα 1 έχουν οι D μονάδες· η διαφάνεια ορίζει: i περιττό → 0, αλλιώς → 1. Με μία βλάβη, ο check disk επιτρέπει ανακατασκευή του χαμένου (το bit που λείπει είναι αυτό που «διορθώνει» την ισοτιμία). Γενίκευση: reliability groups.

Ενημέρωση parity σε RAID-4/5 χωρίς ανάγνωση όλων των D μπλοκ:
NewParity = (OldData ⊕ NewData) ⊕ OldParity
→ μικρή εγγραφή = διάβασε παλιά δεδομένα + παλιά parity, γράψε νέα δεδομένα + νέα parity = 4 I/O.
Take-away (διαφάνεια 58)
Το επίπεδο εξαρτάται από τον φόρτο: RAID-0 βελτιώνει χωρίς κόστος αν η αξιοπιστία δεν μετρά · RAID-0+1 καλύτερο από RAID-1 με πολλές εγγραφές · RAID-2/3 δεν χρησιμοποιούνται (τα καλύπτουν τα 4/5) · RAID-5 > RAID-4 · για 2 ταυτόχρονες βλάβες → RAID-6.
