## 📚 Εισαγωγή: Τι είναι ο Κατακερματισμός

Ο **κατακερματισμός (hashing)** είναι μια τεχνική για **πολύ γρήγορη αναζήτηση** εγγραφών με βάση ένα κλειδί. Αντί να ψάχνουμε σειριακά ή σε δέντρο, χρησιμοποιούμε μια **συνάρτηση κατακερματισμού (hash function)** που "υπολογίζει" απευθείας πού βρίσκεται η εγγραφή.

### 🎯 Βασική Ιδέα

```
Κλειδί K → H(K) = θέση στον πίνακα → Άμεση πρόσβαση!
```

**Παράδειγμα:**

- Έχουμε φοιτητές με ΑΜ (κλειδί)
- Hash function: `H(ΑΜ) = AM mod 100`
- Φοιτητής με ΑΜ=1234567 → θέση 67

### Πλεονεκτήματα vs Μειονεκτήματα

| ✅ Πλεονεκτήματα | ❌ Μειονεκτήματα |
|-----------------|------------------|
| Αναζήτηση O(1) (θεωρητικά) | ΔΕΝ υποστηρίζει range queries |
| Πολύ γρήγορη εισαγωγή | Προβλήματα με συγκρούσεις (collisions) |
| Απλή υλοποίηση | Κακή hash function → κατάρρευση απόδοσης |

## 1. Στατικός Κατακερματισμός (Static Hashing)

### 1.1 Βασικές Έννοιες

**Κάδος (Bucket):** Μία θέση του πίνακα που περιέχει εγγραφές (συνήθως 1 μπλοκ).

**Συνάρτηση Κατακερματισμού H:**

- Είσοδος: Τιμή κλειδιού K
- Έξοδος: Αριθμός bucket (0 έως B-1)

**Τυπικές Hash Functions:**

```
H(K) = K mod B              (για integers)
H(K) = Σ(ASCII(char)) mod B (για strings)
H(K) = CRC32(K) mod B       (για οποιοδήποτε)
```

### 1.2 Δομή Στατικού Hashing

```
Hash Table:
┌─────┬──────────────────┐
│  0  │ → Bucket 0       │
├─────┼──────────────────┤
│  1  │ → Bucket 1       │
├─────┼──────────────────┤
│  2  │ → Bucket 2       │
├─────┼──────────────────┤
│ ... │     ...          │
├─────┼──────────────────┤
│ B-1 │ → Bucket B-1     │
└─────┴──────────────────┘
```

Κάθε bucket:

- Χωρητικότητα C εγγραφών (π.χ. 4)
- Αν γεμίσει → **Overflow Chain** (αλυσίδα υπερχείλισης)

### 1.3 Λειτουργίες

#### Search(K)

1. Υπολόγισε `b = H(K)`
2. Πήγαινε στον bucket b
3. Σάρωσε τον bucket (και overflow chain αν υπάρχει)
4. Επίστρεψε την εγγραφή ή NULL

**Κόστος:**

- Best case: 1 I/O (η εγγραφή στο κύριο bucket)
- Worst case: O(n) αν όλα πήγαν στον ίδιο bucket!

#### Insert(K, R)

1. Υπολόγισε `b = H(K)`
2. Αν ο bucket b έχει χώρο → εισήγαγε
3. Αλλιώς → πρόσθεσε σε overflow chain

#### Delete(K)

1. Βρες και αφαίρεσε
2. (Προαιρετικά: συρρίκνωση overflow chain)

### 1.4 Πρόβλημα: Σταθερό Μέγεθος

**Το βασικό πρόβλημα του στατικού hashing:**

- Ορίζουμε B buckets στην αρχή
- Αν τα δεδομένα μεγαλώσουν → πολλά overflows → αργή αναζήτηση
- Αν τα δεδομένα μειωθούν → πολύ κενός χώρος → σπατάλη

**Λύση:** Δυναμικός κατακερματισμός (π.χ. Επεκτατός)

## 2. Επεκτατός Κατακερματισμός (Extendible Hashing) ⭐

### 2.1 Γιατί Επεκτατός

Ο **Επεκτατός Κατακερματισμός** είναι δυναμικός: το μέγεθος της δομής **προσαρμόζεται αυτόματα** καθώς τα δεδομένα μεγαλώνουν ή μικραίνουν, **χωρίς** πλήρη αναδιοργάνωση!

### 2.2 Βασικές Έννοιες

#### Hash Function

Επιστρέφει **δυαδικό αριθμό** (binary string) μήκους b bits.

**Παράδειγμα:**

```
H("Alice") = 10110101... (32 bits)
H("Bob")   = 01001110...
```

#### Ολικό Βάθος (Global Depth - D)

Πόσα **πρώτα bits** (ή τελευταία, ανάλογα τη σύμβαση) χρησιμοποιούμε για να πλοηγηθούμε στον **κατάλογο (directory)**.

- Μέγεθος καταλόγου = $2^D$ θέσεις

**Παράδειγμα:** Αν D=2 → κατάλογος με 4 θέσεις (00, 01, 10, 11)

#### Τοπικό Βάθος (Local Depth - d')

Πόσα bits "κοιτάει" ένας συγκεκριμένος **κάδος (bucket)**.

**Σημαντική ιδιότητα:** Πάντα $d' \le D$

**Τι σημαίνει d' < D;**

- Ο κάδος "μοιράζεται" από πολλές θέσεις του καταλόγου
- Συγκεκριμένα: $2^{D-d'}$ θέσεις δείχνουν στον ίδιο κάδο

#### Κατάλογος (Directory)

Πίνακας με $2^D$ δείκτες προς κάδους.

```
D = 2 (Global Depth)
┌──────┬─────────────┐
│ 00   │ → Bucket A  │ (d'=2)
│ 01   │ → Bucket B  │ (d'=1)
│ 10   │ → Bucket C  │ (d'=2)
│ 11   │ → Bucket B  │ (d'=1) ← Ίδιος bucket με 01!
└──────┴─────────────┘
```

Στο παράδειγμα:

- Bucket B έχει d'=1 → δείχνεται από 01 και 11 (διαφέρουν μόνο στο πρώτο bit)

### 2.3 Δομή Κάδου

Κάθε κάδος περιέχει:

- **Εγγραφές:** Μέχρι C εγγραφές (χωρητικότητα)
- **Τοπικό βάθος d':** Metadata

```
Bucket A (d'=2):
┌──────────────┬───┐
│ [K1, R1]     │   │
│ [K2, R2]     │ 2 │ ← d'
│ [K3, R3]     │   │
│ (κενό)       │   │
└──────────────┴───┘
```

## 3. Αλγόριθμοι Επεκτατού Κατακερματισμού

### 3.1 Αναζήτηση (Lookup)

**Είσοδος:** Κλειδί K

1. Υπολόγισε `h = H(K)` (π.χ. 101101...)
2. Πάρε τα **D πρώτα bits** του h
3. Χρησιμοποίησέ τα ως δείκτη στον κατάλογο
4. Ακολούθησε τον δείκτη στον κάδο
5. Σάρωσε τον κάδο για το K

**Παράδειγμα:**

```
D = 3, H(K) = 10110101
Πρώτα 3 bits: 101
→ Κοίτα στη θέση 101 του καταλόγου
→ Πήγαινε στον κάδο που δείχνει
```

**Κόστος:** 1 I/O (directory στη μνήμη) + 1 I/O (bucket)

### 3.2 Εισαγωγή (Insert) - **ΚΡΙΣΙΜΟ**

**Είσοδος:** Κλειδί K, Εγγραφή R

#### Βήμα 1: Βρες τον κάδο

1. Υπολόγισε `h = H(K)`
2. Πάρε D bits → θέση καταλόγου → κάδος B

#### Βήμα 2: Προσπάθησε να εισάγεις

- **Αν ο B έχει χώρο (< C εγγραφές):**
  - Εισήγαγε και τέλος ✓

- **Αν ο B είναι ΓΕΜΑΤΟΣ (Overflow):**
  - Πήγαινε στο Βήμα 3

#### Βήμα 3: Έλεγξε d' vs D

##### **ΠΕΡΙΠΤΩΣΗ Α: d' < D** (Υπάρχει "περιθώριο")

Ο κάδος μπορεί να διασπαστεί χωρίς να διπλασιάσουμε τον κατάλογο.

**Δράσεις:**

1. **Διάσπαση Κάδου (Split Bucket):**
   - Δημιούργησε νέο κάδο B'
   - Και τα δύο (B και B') θα έχουν d' = d'+1

2. **Ανακατανομή (Rehash):**
   - Για κάθε εγγραφή στον παλιό κάδο:
     - Κοίτα το bit στη θέση d'+1 του hash
     - Αν 0 → μένει στον B
     - Αν 1 → πάει στον B'

3. **Ενημέρωση Καταλόγου:**
   - Όλες οι θέσεις που έδειχναν στον B:
     - Αν το bit στη θέση d'+1 είναι 0 → δείχνουν στον B
     - Αν το bit στη θέση d'+1 είναι 1 → δείχνουν στον B'

##### **ΠΕΡΙΠΤΩΣΗ Β: d' = D** (Δεν χωράει ο κατάλογος)

Χρειάζεται πρώτα να μεγαλώσει ο κατάλογος.

**Δράσεις:**

1. **Διπλασιασμός Καταλόγου (Directory Doubling):**
   - D = D + 1
   - Νέο μέγεθος = $2^{D}$ θέσεις

2. **Αντιγραφή Δεικτών:**
   - Κάθε θέση `xxx` του παλιού καταλόγου → δύο θέσεις `0xxx` και `1xxx` του νέου
   - Αρχικά και οι δύο δείχνουν στον ίδιο κάδο

3. **Τώρα d' < D:**
   - Εφάρμοσε την **ΠΕΡΙΠΤΩΣΗ Α**

#### ✏️ Solved Example: Insert με Split

**Αρχική Κατάσταση:**

```
D = 2, Χωρητικότητα κάδου = 2

Κατάλογος:        Κάδοι:
┌────┬─────┐
│ 00 │ → A │ → [10, 20] (d'=2)
│ 01 │ → B │ → [5]      (d'=1)
│ 10 │ → C │ → [18, 26] (d'=2)
│ 11 │ → B │ /          (d'=1)
└────┴─────┘
```

**Εισάγουμε κλειδί 13 με H(13) = 00...**

1. Πρώτα 2 bits = 00 → Κάδος A
2. Ο A είναι γεμάτος [10, 20] → **Overflow!**
3. d'(A) = 2, D = 2 → **d' = D** → Χρειάζεται διπλασιασμός!

**Μετά τον Διπλασιασμό:**

```
D = 3 (νέο)

Κατάλογος:        
┌─────┬─────┐
│ 000 │ → A │ (d'=2 ακόμα)
│ 001 │ → B │ 
│ 010 │ → C │ 
│ 011 │ → B │
│ 100 │ → A │ (δείχνει στον ίδιο Α)
│ 101 │ → B │
│ 110 │ → C │
│ 111 │ → B │
└─────┴─────┘
```

1. Τώρα d'(A)=2 < D=3 → **Μπορούμε να κάνουμε split!**
2. **Split του A:**
   - Νέος κάδος A' με d'=3
   - Παλιός A τώρα d'=3
   - Κοιτάμε το 3ο bit των hash:
     - H(10) = 000... → μένει στον A
     - H(20) = 100... → πάει στον A'
     - H(13) = 000... → πάει στον A

**Τελικό:**

```
D = 3

Κατάλογος:        Κάδοι:
┌─────┬─────┐
│ 000 │ → A │ → [10, 13] (d'=3)
│ 001 │ → B │ → [5]      (d'=1)
│ 010 │ → C │ → [18, 26] (d'=2)
│ 011 │ → B │ /
│ 100 │ → A'│ → [20]     (d'=3)
│ 101 │ → B │ /
│ 110 │ → C │ /
│ 111 │ → B │ /
└─────┴─────┘
```

### 3.3 Διαγραφή (Delete) - Προαιρετικό

**Βασική Ροή:**

1. Βρες και διέγραψε την εγγραφή
2. Αν ο κάδος αδειάσει πολύ, μπορεί να συγχωνευτεί με τον **buddy** του

**Buddy Buckets:** Δύο κάδοι που διαφέρουν μόνο στο τελευταίο bit.

- Π.χ. κάδος 1010 και 1011

**Συγχώνευση:**

- Αν Α και Α' είναι buddies με d'(A) = d'(A') = d
- Και μαζί έχουν $\le C$ εγγραφές
- → Ένωσέ τους σε ένα με d' = d-1

**Υποδιπλασιασμός (Directory Halving):**

- Αν ΟλΟΙ οι κάδοι έχουν d' < D
- → Μείωσε το D κατά 1 και μίσεψε τον κατάλογο

> 💡 **Σημείωση:** Η διαγραφή σπάνια εξετάζεται. Focus στην εισαγωγή!

## 4. Ανάλυση & Κόστος

### 4.1 Πολυπλοκότητα

| Λειτουργία | Μέση Περίπτωση | Χειρότερη |
|------------|-----------------|-----------|
| Search | O(1) | O(log n) |
| Insert | O(1) amortized | O(n) (rare) |
| Delete | O(1) amortized | O(n) |

**Γιατί "amortized O(1)";**

- Τα περισσότερα inserts είναι γρήγορα (1-2 I/Os)
- Σπάνια γίνεται split (κόστος αναλογικό στο μέγεθος κάδου, όχι n)
- Πολύ σπάνια διπλασιασμός καταλόγου

### 4.2 Πλεονεκτήματα Επεκτατού

✅ **Δυναμική προσαρμογή:** Χωρίς πλήρη αναδιοργάνωση
✅ **Χαμηλό κόστος split:** Μόνο ένας κάδος επηρεάζεται
✅ **Καλή χρήση χώρου:** Λίγα overflows

### 4.3 Μειονεκτήματα

❌ **Directory overhead:** Ο κατάλογος μπορεί να μεγαλώσει πολύ ($2^D$ θέσεις)
❌ **Δεν υποστηρίζει ranges:** Όπως όλα τα hashing schemes
❌ **Skewed distributions:** Αν πολλά κλειδιά έχουν ίδιο hash → ένας κάδος γεμίζει συνέχεια

## 5. Γραμμικός Κατακερματισμός (Linear Hashing) - Συνοπτικά

Εναλλακτική δυναμική μέθοδος **ΧΩΡΙΣ κατάλογο**.

### Βασική Ιδέα

- Χρησιμοποιεί δείκτη **Next** που δείχνει ποιος κάδος θα κάνει split επόμενος
- Το split γίνεται **ανεξάρτητα** από το overflow (Round-Robin)
- Χρησιμοποιεί 2 hash functions: $h_L$ και $h_{L+1}$ (διαφορετικό modulo)

### Πότε γίνεται Split

Όταν ο **load factor** (πληρότητα) ξεπεράσει κάποιο threshold (π.χ. 75%).

**Παράδειγμα:**

```
Buckets: [0, 1, 2, 3]
Next = 0
Load factor > 0.75 → Split bucket 0
Next = 1
... και ούτω καθεξής
```

> 💡 Ο Γραμμικός είναι λιγότερο συχνός στις εξετάσεις από τον Επεκτατό.

## 6. Στρατηγική Εξετάσεων

### 6.1 Τύποι Ερωτήσεων

#### Ερώτηση Τύπου Α: Σχεδιασμός από την αρχή
>
> "Δημιουργήστε Επεκτατό Hashing με D=2, capacity=3. Εισάγετε τα κλειδιά [12, 5, 18, 23, 7, 14]."

**Μεθοδολογία:**

1. Ορίστε hash function (συνήθως δίνεται πίνακας)
2. Ξεκινήστε με έναν κάδο (d'=0, D=0) ή όπως λέει η εκφώνηση
3. Για κάθε εισαγωγή:
   - Γράψτε το hash σε binary
   - Δείξτε ποιον κάδο επιλέγετε
   - Αν overflow → σχεδιάστε το split βήμα-βήμα

#### Ερώτηση Τύπου Β: Εισαγωγή σε υπάρχον
>
> "Δίνεται το παρακάτω Extendible Hashing. Εισάγετε το κλειδί X."
>
> - Ποιο θα είναι το νέο D;
> - Πόσοι κάδοι θα υπάρχουν;
> - Τι περιέχει ο κάδος με d'=...;

**Tips:**

- Προσοχή στα **bits** (LSB vs MSB - δείτε τη σύμβαση της εκφώνησης!)
- Σημειώστε τα d' σε κάθε κάδο
- Υπολογίστε ποιες θέσεις του directory δείχνουν πού

### 6.2 Πίνακας Hash Τιμών (Συχνό!)

Ο καθηγητής συχνά δίνει:

```
"Το 3ο γράμμα του επωνύμου σας ορίζει το κλειδί προς εισαγωγή.
Χρησιμοποιήστε τον παρακάτω πίνακα:"

Α → 00101
Β → 10011
Γ → 01110
...
```

**Στρατηγική:**

1. Βρες το γράμμα σου
2. Πάρε τα D πρώτα (ή τελευταία) bits
3. Συνέχισε κανονικά

### 6.3 Checklist Πριν Απάντηση

- [ ] Ξέρω αν χρησιμοποιώ MSB (πρώτα) ή LSB (τελευταία) bits?
- [ ] Έχω σημειώσει το d' σε **ΚΑΘΕ** κάδο;
- [ ] Υπολογίζω σωστά πόσες θέσεις του directory δείχνουν σε κάθε κάδο;
- [ ] Έλεγξα αν d' = D πριν το split (για διπλασιασμό);
- [ ] Μετά το split, ενημέρωσα τα d';

## 7. Συχνές Παγίδες

❌ **ΛΑΘΟΣ:** "Κάνω πάντα διπλασιασμό όταν γεμίσει κάδος"
✅ **ΣΩΣΤΟ:** Διπλασιασμός **ΜΟΝΟ** αν d' = D

❌ **ΛΑΘΟΣ:** "Μετά το split, ο νέος κάδος έχει d' = d'+2"
✅ **ΣΩΣΤΟ:** Και οι δύο έχουν d' = (παλιό d') + 1

❌ **ΛΑΘΟΣ:** "Το directory είναι πάντα στο δίσκο"
✅ **ΣΩΣΤΟ:** Συνήθως **στη μνήμη** (είναι μικρό, $2^D$ pointers)

❌ **ΛΑΘΟΣ:** "Χρησιμοποιώ ΟΛΑ τα bits του hash"
✅ **ΣΩΣΤΟ:** Μόνο τα **D πρώτα** (ή τελευταία)

## 8. Σύγκριση Hashing Schemes

| Χαρακτηριστικό | Static | Extendible | Linear |
|----------------|--------|------------|--------|
| **Δυναμικό** | ✗ | ✓ | ✓ |
| **Directory** | ✗ | ✓ | ✗ |
| **Overflows** | Πολλά | Λίγα | Μέτρια |
| **Split strategy** | - | On demand | Round-robin |
| **Worst-case search** | O(n) | O(log n) | O(n) |
| **Space overhead** | Χαμηλό | Μεσαίο (directory) | Χαμηλό |

---

## 9. Σύγκριση με B+ Trees

| Κριτήριο | B+ Trees | Extendible Hashing |
|----------|----------|-------------------|
| **Equality search** | O(log n) | O(1) ✓ |
| **Range queries** | O(log n + k) ✓ | ✗ (δεν υποστηρίζει) |
| **Ταξινομημένα δεδομένα** | ✓ (φύλλα linked) | ✗ |
| **Insertions** | O(log n) | O(1) amortized ✓ |
| **Space efficiency** | Πολύ καλή | Καλή |

**Πότε να χρησιμοποιήσεις ποιο;**

- **B+ Tree:** Αν χρειάζεσαι range queries ή ταξινόμηση
- **Extendible Hash:** Αν κάνεις ΜΟΝΟ equality lookups (π.χ. dictionary, cache)

## 10. Τυπολόγιο

### Μέγεθος Directory

```
Μέγεθος = 2^D θέσεις (pointers)
```

### Πλήθος Θέσεων που δείχνουν σε κάδο με d'

```
Θέσεις = 2^(D - d')
```

### Load Factor (Παράγοντας Φόρτου)

```
LF = (Σύνολο εγγραφών) / (Αριθμός κάδων × Χωρητικότητα)
```

**Ιδανικό:** 0.7 - 0.8 (70-80% γεμάτοι)

## 11. Πρακτικά Παραδείγματα

### Παράδειγμα 1: Hash Function με Strings

```
Hash("Alice") = Σ(ASCII values) mod 16 = (65+108+105+99+101) mod 16 = 478 mod 16 = 14
Binary: 1110

Αν D=3 → χρησιμοποιούμε "111" (τα 3 LSB ή MSB)
```

### Παράδειγμα 2: Υπολογισμός πόσοι δείχνουν σε κάδο

```
D = 4, Bucket X έχει d' = 2

Πόσες θέσεις του directory δείχνουν στον X?
2^(D - d') = 2^(4-2) = 2^2 = 4 θέσεις ✓
```
