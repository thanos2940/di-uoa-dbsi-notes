## 📚 Μέρος Α: Timestamp Ordering (Χρονοσφραγίδες)

### 1. Βασική Ιδέα

**Εναλλακτική του 2PL:** Αντί για locks, χρησιμοποιούμε **timestamps** για να ορίσουμε τη σειρά εκτέλεσης.

**Κάθε δοσοληψία $T_i$ παίρνει ένα timestamp $TS(T_i)$ στην έναρξή της.**

```
T₁ ξεκινάει στις 10:00:00 → TS(T₁) = 1000000
T₂ ξεκινάει στις 10:00:01 → TS(T₂) = 1000001
```

**Κανόνας:** Η σειριά των timestamps = serialization order.

### 2. Metadata ανά Αντικείμενο

Για κάθε αντικείμενο X, κρατάμε:

- **R-TS(X):** Το μεγαλύτερο timestamp δοσοληψίας που **διάβασε** το X
- **W-TS(X):** Το μεγαλύτερο timestamp δοσοληψίας που **έγραψε** το TS(X)

### 3. Πρωτόκολλο

#### Κανόνας Read

```
Αν T_i θέλει να διαβάσει το X:
  Αν TS(T_i) < W-TS(X):
    → Abort T_i  [Προσπαθεί να διαβάσει "μελλοντική" τιμή]
  Αλλιώς:
    → Επιτρέπεται
    → R-TS(X) = max(R-TS(X), TS(T_i))
```

#### Κανόνας Write

```
Αν T_i θέλει να γράψει το X:
  Αν TS(T_i) < R-TS(X):
    → Abort T_i  [Μια νεότερη δοσοληψία διάβασε ήδη αλλη τιμή]
  Αν TS(T_i) < W-TS(X):
    → Abort T_i  [Μια νεότερη δοσοληψία έγραψε ήδη]
  Αλλιώς:
    → Επιτρέπεται
    → W-TS(X) = TS(T_i)
```

### 4. Thomas Write Rule (Ειδική Εξαίρεση)

**Βελτιστοποίηση** για WW συγκρούσεις:

```
Αν TS(T_i) < W-TS(X):
  Αντί για Abort → **ΑΓΝΟΗΣΕ** την εγγραφή!
```

**Λογική:** Η εγγραφή του $T_i$ είναι "παρωχημένη" (obsolete). Μια νεότερη δοσοληψία έχει ήδη γράψει, οπότε η παλιά τιμή δεν χρειάζεται.

**Παράδειγμα:**

```
T₁ (TS=100): W[X]
T₂ (TS=200):      W[X]  C
T₁:               W[X]  ← TS(T₁)=100 < W-TS(X)=200

Thomas Write Rule: Αγνόησε το W[X] του T₁ (είναι obsolete)
→ T₁ συνεχίζει (δεν χρειάζεται abort)
```

### 5. Πλεονεκτήματα & Μειονεκτήματα

| ✅ Πλεονεκτήματα | ❌ Μειονεκτήματα |
|-----------------|------------------|
| Δεν έχει deadlocks | Πολλά aborts (starvation) |
| Δεν χρειάζεται locks | Overhead από restarts |
| Εξασφαλίζει serializability | Δεν είναι ανθεκτικό σε skew |

## 📝 Μέρος Β: Cheat Sheet για Εξετάσεις

### 1. Σωστό/Λάθος (12 Μονάδες) - Κρίσιμες Ερωτήσεις

#### Θέμα: Σειριοποιησιμότητα & Γράφοι

**Ερώτηση 1:**
> "Ακυκλικός precedence graph συνεπάγεται ότι το schedule είναι σειριοποιήσιμο."

✅ **ΣΩΣΤΟ**  
(Αυτό είναι το **θεώρημα της σειριοποιησιμότητας**)

**Ερώτηση 2:**
> "Κυκλικός precedence graph συνεπάγεται deadlock."

❌ **ΛΑΘΟΣ**  

- Precedence graph → **λογική ασυνέπεια** (serializability)
- Wait-For graph → **φυσικό κόλλημα** (deadlock)
- Είναι **ανεξάρτητα**!

**Ερώτηση 3:**
> "Κυκλικός precedence graph συνεπάγεται ότι το schedule ΔΕΝ είναι σειριοποιήσιμο."

❌ **ΛΑΘΟΣ** (tricky!)  

- Conflict serializability ≠ View serializability
- Ένα schedule μπορεί να είναι view serializable αλλά όχι conflict serializable
- Ο κυκλικός γράφος σημαίνει **ΔΕΝ είναι conflict serializable**, αλλά **δεν ξέρουμε** αν είναι serializable γενικά!

#### Θέμα: 2PL

**Ερώτηση 4:**
> "2PL εγγυάται σειριοποιησιμότητα."

✅ **ΣΩΣΤΟ**  
(Αυτό είναι το **θεώρημα 2PL**)

**Ερώτηση 5:**
> "2PL αποτρέπει deadlocks."

❌ **ΛΑΘΟΣ** (κλασική παγίδα!)  
2PL → Serializability, **ΟΧΙ** deadlock-freedom.

**Ερώτηση 6:**
> "Strict 2PL κρατάει όλα τα locks μέχρι commit."

❌ **ΛΑΘΟΣ**  

- **Strict 2PL:** Κρατάει μόνο τα **X-locks** μέχρι commit
- **Rigorous 2PL:** Κρατάει **όλα** (S και X) μέχρι commit

#### Θέμα: Σχεσιακή Άλγεβρα

**Ερώτηση 7:**
> "R ⋈ (S ∪ T) = (R ⋈ S) ∪ (R ⋈ T)"

✅ **ΣΩΣΤΟ**  
(Διανομή της ζεύξης στην ένωση)

**Ερώτηση 8:**
> "σ_{θ}(R ⋈ S) = σ_{θ}(R) ⋈ S για οποιοδήποτε θ."

❌ **ΛΑΘΟΣ**  
Μόνο αν το θ αφορά **μόνο πεδία του R**.

**Ερώτηση 9:**
> "Η προβολή αφαιρεί πάντα duplicates."

❌ **ΛΑΘΟΣ** (στο SQL)  
Χωρίς `DISTINCT`, δεν αφαιρούνται.

#### Θέμα: B+ Trees & Hashing

**Ερώτηση 10:**
> "Το B+ Tree είναι πάντα ισορροπημένο."

✅ **ΣΩΣΤΟ**  
(Εξ ορισμού, όλα τα φύλλα στο ίδιο βάθος)

**Ερώτηση 11:**
> "Το hashing υποστηρίζει range queries αποδοτικά."

❌ **ΛΑΘΟΣ**  
Hash → μόνο **equality** lookups.

**Ερώτηση 12:**
> "Στο επεκτατό hashing, η directory doubling γίνεται πάντα όταν γεμίσει κάδος."

❌ **ΛΑΘΟΣ**  
Μόνο όταν d' = D (όταν ο κάδος δεν έχει άλλο "περιθώριο").

### 2. Υπολογισμοί & Τυπολόγιο (Quick Reference)

#### B+ Trees

```
Search:  d(I) = O(log_d n)
Insert:  d(I) + splits
Delete:  d(I) + merges
Range:   d(I) + matching_pages
```

#### Join Costs

```
Simple NL:     p(R) + t(R) × p(S)
Block NL:      p(R) + ⌈p(R)/(M-2)⌉ × p(S)
Sort-Merge:    Sort(R) + Sort(S) + p(R) + p(S)
Hash:          3(p(R) + p(S))
```

#### Selection (με index)

```
Clustered:     d(I) + ⌈p(R) / V(A,R)⌉
Non-clustered: d(I) + t(R) / V(A,R)
```

#### Selectivity

```
Equality:      1 / V(A,R)
Range:         (max - c) / (max - min)
Conjunction:   S₁ × S₂
```

### 3. Μεθοδολογία για Ασκήσεις

#### B+ Tree Insert/Delete

1. **Διάβασε χωρητικότητα** (max keys, max pointers)
2. **Σχεδίασε βήμα-βήμα** (μην κάνεις skip!)
3. **Προσοχή:**
   - Φύλλα: **COPY UP**
   - Εσωτερικοί: **PUSH UP**
4. **Έλεγξε:** Όλα τα φύλλα ίδιο βάθος;

#### Extendible Hashing

1. **MSB ή LSB?** (Διάβασε εκφώνηση!)
2. **Για κάθε κάδο:** Σημείωσε d'
3. **Πριν split:** Έλεγξε d' vs D
4. **Αν d' = D:** Διπλασιασμός directory **πρώτα**
5. **Μετά split:** d' = d'+1 για **αμφότερους**

#### Join Cost

1. **p(R), p(S), M** (από εκφώνηση)
2. **Ποιος outer?** Ο μικρότερος (σε pages!)
3. **Τύποι:**
   - Block NL: $p(R) + \lceil p(R)/(M-2) \rceil \times p(S)$
   - Hash: $3(p(R) + p(S))$
4. **Μονάδες:** I/Os

#### Serializability

1. **Βρες συγκρούσεις:** Ίδιο αντικείμενο, διαφορετικές Tx, τουλάχιστον 1 write
2. **Σχεδίασε γράφο:** Κόμβοι = Transactions, Ακμές = Conflicts
3. **Έλεγχος κύκλου:** DFS ή inspection
4. **Αν ακυκλικός:** Serializable! (Topological sort → serial order)

---

### 4. Συχνές Παγίδες (DON'T DO THIS!)

❌ **"p(R) = αριθμός εγγραφών"**  
✅ p(R) = αριθμός **μπλοκ** (pages)

❌ **"Hash Join cost = 2(p(R) + p(S))"**  
✅ Hash Join = **3**(p(R) + p(S))

❌ **"RR είναι σύγκρουση"**  
✅ Read-Read **ΔΕΝ** συγκρούονται

❌ **"Precedence graph cycle = Deadlock"**  
✅ **ΟΧΙ!** Precedence → serializability, Wait-For → deadlock

❌ **"Clustered index: πολλά ανά πίνακα"**  
✅ **ΕΝΑ μόνο** clustered (φυσική διάταξη)
