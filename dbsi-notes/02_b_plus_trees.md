## 📚 Γιατί B+ Trees

Τα B+ Trees είναι η **πιο σημαντική** δομή δεδομένων στα συστήματα βάσεων δεδομένων. Χρησιμοποιούνται σχεδόν σε όλες τις εμπορικές βάσεις (MySQL/InnoDB, PostgreSQL, Oracle, SQL Server) για indexing.

### Πλεονεκτήματα έναντι άλλων δομών

- ✅ **Δυναμική προσαρμογή** (σε αντίθεση με το ISAM που είναι στατικό)
- ✅ **Πάντα ισορροπημένο** (όλα τα φύλλα στο ίδιο βάθος)
- ✅ **Αποδοτικό για range queries** (φύλλα συνδεδεμένα σε λίστα)
- ✅ **Υψηλός fan-out** (πολλά παιδιά ανά κόμβο → μικρό ύψος)
- ✅ **Χαμηλό κόστος ενημερώσεων** (αντίθετα με ταξινομημένα αρχεία)

## 1. Βασικά Χαρακτηριστικά & Ορισμοί

### 1.1 Τάξη (Order) - Παράμετρος $d$

Η τάξη $d$ καθορίζει τη χωρητικότητα κάθε κόμβου:

- **Εσωτερικοί κόμβοι:** $[d, 2d]$ κλειδιά (εκτός ρίζας)
- **Φύλλα:** $[d, 2d]$ κλειδιά (εκτός ρίζας)
- **Ρίζα:** $[1, 2d]$ κλειδιά (ειδική περίπτωση)

#### 💡 Σημείωση

Ο καθηγητής Ιωαννίδης **δεν δίνει** το $d$ απευθείας. Θα πει:
> "Κάθε εσωτερικός κόμβος έχει max 4 δείκτες και 3 τιμές. Κάθε φύλλο χωράει max 3 εγγραφές."

Εσείς πρέπει να καταλάβετε ότι:

- Max 3 τιμές → $2d = 3$ → $d = 1.5$ ❌ (όχι ακέραιος!)
- **Σωστή ερμηνεία:** Max 3 κλειδιά = capacity 3, οπότε ελάχιστο = ⌈3/2⌉ = 2

### 1.2 Δομή Κόμβων

#### Εσωτερικός Κόμβος (Index Node)

```
┌────┬────┬────┬────┬────┬────┬────┐
│ P₀ │ K₁ │ P₁ │ K₂ │ P₂ │ K₃ │ P₃ │
└────┴────┴────┴────┴────┴────┴────┘
```

- $P_i$ = δείκτης (pointer) σε child node
- $K_i$ = τιμή κλειδιού (separator/guide)
- **Ιδιότητα:** Αν κόμβος έχει $n$ κλειδιά → έχει $n+1$ δείκτες
- **Σειρά:** $K_1 < K_2 < \ldots < K_n$

**Σεμασιολογία:**

- Όλα τα κλειδιά στο υποδέντρο $P_0$ είναι $< K_1$
- Όλα τα κλειδιά στο υποδέντρο $P_i$ (για $i > 0$) είναι $\ge K_i$ και $< K_{i+1}$

#### Φύλλο (Leaf Node)

```
┌────────┬────────┬────────┬───┐
│(K₁,R₁)│(K₂,R₂)│(K₃,R₃)│ → │
└────────┴────────┴────────┴───┘
```

- $K_i$ = τιμή κλειδιού
- $R_i$ = Row ID (RID) ή δείκτης σε data record
- **→** = δείκτης στο επόμενο φύλλο (για sequential scan)

> ⚠️ **ΕΞΕΤΑΣΤΙΚΟ:** Τα φύλλα περιέχουν τα **πραγματικά δεδομένα** (ή δείκτες σε αυτά). Οι εσωτερικοί κόμβοι μόνο "οδηγούς".

## 2. Βασικοί Αλγόριθμοι

### 2.1 Αναζήτηση (Search)

**Κόστος:** $O(\log_d n)$ = $d(I)$ (βάθος ευρετηρίου)

**Αλγόριθμος:**

1. Ξεκίνα από τη ρίζα
2. Αν είσαι σε φύλλο:
   - Αναζήτησε γραμμικά το κλειδί $K$
   - Επίστρεψε το RID αν βρεθεί, αλλιώς NULL
3. Αν είσαι σε εσωτερικό κόμβο με κλειδιά $[K_1, K_2, \ldots, K_n]$:
   - Αν $K < K_1$ → ακολούθησε $P_0$
   - Αν $K_i \le K < K_{i+1}$ → ακολούθησε $P_i$
   - Αν $K \ge K_n$ → ακολούθησε $P_n$
4. Επανέλαβε από βήμα 2

#### ✏️ Solved Example: Search for 27

```
         [20, 40]
        /    |    \
    [10,15] [25,30] [50]
    
Βήμα 1: Root → 27 ≥ 20 and 27 < 40 → P₁ (μέσος δείκτης)
Βήμα 2: [25,30] → 27 ≥ 25 and 27 < 30 → P₁
Βήμα 3: Φύλλο [25, 27, 28] → Βρέθηκε!
```

---

### 2.2 Εισαγωγή (Insertion) - **ΚΡΙΣΙΜΟ**

#### Βασική Ροή

1. Βρες το κατάλληλο φύλλο $L$ (με Search)
2. **Αν το $L$ έχει χώρο** (< max κλειδιά):
   - Εισήγαγε το κλειδί ταξινομημένα
   - Τέλος
3. **Αν το $L$ είναι ΓΕΜΑΤΟ (Overflow):**
   - **SPLIT LEAF**

#### Αλγόριθμος Split Leaf

1. Δημιούργησε νέο φύλλο $L'$
2. Μοίρασε τα κλειδιά (**μαζί με το νέο**):
   - Πρώτα ⌈$(n+1)/2$⌉ → $L$
   - Υπόλοιπα → $L'$
3. **COPY UP:** Αντέγραψε το μικρότερο κλειδί του $L'$ στον γονέα
4. Σύνδεσε $L \to L'$ (next pointer)
5. Ενημέρωσε τον γονέα:
   - Πρόσθεσε το κλειδί που ανέβηκε
   - Πρόσθεσε δείκτη στο $L'$
6. **Αν ο γονέας γεμίσει** → SPLIT PARENT

#### Αλγόριθμος Split Internal Node

1. Δημιούργησε νέο κόμβο $N'$
2. Έστω $m$ = μεσαίο κλειδί (median)
3. Μοίρασε:
   - Κλειδιά πριν το $m$ → $N$
   - Κλειδιά μετά το $m$ → $N'$
   - **PUSH UP:** Το $m$ ανεβαίνει στον γονέα (ΔΕΝ μένει στον $N$ ούτε στον $N'$)
4. Αναδρομικά αν ο γονέας γεμίσει

> 💡 **Ο καθηγητής τονίζει:**
>
> - Στα **φύλλα**: **COPY UP** (το κλειδί μένει ΚΑΙ ανεβαίνει)
> - Στους **εσωτερικούς**: **PUSH UP** (το κλειδί φεύγει και πάει πάνω)

#### ✏️ Solved Example: Insert 8

**Αρχικό δέντρο (d=1, max 2 κλειδιά ανά φύλλο):**

```
         [10]
        /    \
    [5, 7]  [10, 15]
```

**Εισάγουμε 8:**

1. Search → φύλλο [5, 7]
2. Προσπαθούμε να βάλουμε το 8 → [5, 7, 8] → **Overflow!**
3. **Split:**
   - $L$ = [5, 7]
   - $L'$ = [8]
   - COPY UP το 8 στον γονέα
4. **Νέο δέντρο:**

```
         [8, 10]
        /   |    \
    [5,7]  [8]  [10,15]
```

#### ⚠️ EXAM WARNING: Ειδική Περίπτωση Ρίζας

Αν η ρίζα κάνει split:

- Δημιουργείται **ΝΕΑ ΡΙΖΑ** με 1 μόνο κλειδί (το promoted)
- Το ύψος του δέντρου **αυξάνεται κατά 1**
- Αυτός είναι ο **ΜΟΝΟΣ** τρόπος να μεγαλώσει το δέντρο σε ύψος!

---

### 2.3 Διαγραφή (Deletion) - **ΚΡΙΣΙΜΟ**

#### Βασική Ροή

1. Βρες το φύλλο και διέγραψε το κλειδί
2. **Αν το φύλλο έχει $\ge d$ κλειδιά** → OK, τέλος
3. **Αν Underflow (< d):**
   - Προσπάθησε **Redistribution** (δανεισμό)
   - Αλλιώς **Merge** (συγχώνευση)

#### Redistribution (Δανεισμός)

**Προϋπόθεση:** Ο αδελφός έχει **περίσσεια** (> d κλειδιά)

**Βήματα:**

1. Πάρε ένα κλειδί από τον αδελφό
2. Ενημέρωσε τον διαχωριστή στον γονέα

**Παράδειγμα:**

```
Πριν:  [5] | [10]     ← γονέας
       [3] [7, 8, 9]  ← φύλλα

Διαγράφουμε 3 από αριστερό φύλλο → Underflow!
Ο δεξιός αδελφός έχει 3 κλειδιά (> d=1) → Μπορούμε να δανειστούμε

Μετά: [7] | [10]     ← γονέας (ενημερώθηκε)
      [3→7] [8, 9]   ← πήραμε το 7
```

#### Merge (Συγχώνευση)

**Προϋπόθεση:** Ο αδελφός έχει **ακριβώς** $d$ κλειδιά (δεν έχει περίσσεια)

**Βήματα:**

1. Ένωσε τα δύο φύλλα σε ένα
2. **Pull Down:** Κατέβασε τον διαχωριστή από τον γονέα (μόνο για εσωτερικούς!)
3. Διέγραψε τον κενό κόμβο
4. **Αναδρομικά**: Έλεγξε αν ο γονέας έχει underflow

**Παράδειγμα Merge:**

```
Πριν:    [10, 20]
        /   |    \
    [5,7] [12] [25,30]

Διαγράφουμε 12 → Underflow! (< 2)
Αδελφοί: [5,7] (=2) και [25,30] (=2) → Δεν έχουν περίσσεια
→ MERGE με αριστερό

Μετά:      [20]
          /    \
    [5, 7, 10] [25,30]
    
(Το 10 κατέβηκε από τον γονέα - PULL DOWN)
```

> ⚠️ **ΕΞΕΤΑΣΤΙΚΟ:** Pull Down γίνεται **ΜΟΝΟ σε εσωτερικούς κόμβους**, όχι σε φύλλα!

#### Ειδική Περίπτωση: Merge της Ρίζας

Αν η ρίζα μείνει με 1 μόνο παιδί:

- Το παιδί γίνεται η νέα ρίζα
- Το ύψος μειώνεται κατά 1

## 3. Πολυπλοκότητα & Κόστος

| Λειτουργία | Χρονική Πολυπλοκότητα | I/O Κόστος |
|------------|----------------------|------------|
| Search | $O(\log_d n)$ | $d(I)$ |
| Insert | $O(\log_d n)$ | $d(I) + 1$ ή $2 \cdot d(I)$ (αν split) |
| Delete | $O(\log_d n)$ | $d(I) + 1$ ή $2 \cdot d(I)$ (αν merge) |
| Range Query | $O(\log_d n + k)$ | $d(I) + \lceil k/f \rceil$ |

Όπου:

- $d$ = order (fan-out)
- $n$ = αριθμός κλειδιών
- $d(I)$ = βάθος ευρετηρίου
- $k$ = πλήθος αποτελεσμάτων
- $f$ = κλειδιά ανά φύλλο

### 💡 Γιατί τα B+ Trees είναι γρήγορα

Με $d = 100$ (τυπικό για block 4KB):

- 1,000,000 κλειδιά → ύψος ≈ 3
- 1,000,000,000 κλειδιά → ύψος ≈ 5
- **Άρα 5 I/Os max για οποιαδήποτε αναζήτηση!**

## 4. Στρατηγική Εξετάσεων

### 4.1 Τύποι Ερωτήσεων

1. **Κατασκευή δέντρου από την αρχή**
   - Δίνονται τιμές (συχνά από ΑΜ)
   - Ζητείται βήμα-βήμα εισαγωγή
2. **Εισαγωγή σε υπάρχον δέντρο**
   - Δίνεται δέντρο και νέα τιμή
   - "Ποια κλειδιά θα είναι στη ρίζα μετά την εισαγωγή;"
3. **Διαγραφή από υπάρχον δέντρο**
   - Δίνεται δέντρο και τιμή προς διαγραφή
   - "Σχεδιάστε το τελικό δέντρο"

### 4.2 Μεθοδολογία Επίλυσης

1. **Διάβασε ΠΡΟΣΕΚΤΙΚΑ** τη χωρητικότητα:
   - "Max 4 pointers" → 3 κλειδιά max
   - "Φύλλο χωράει 3 εγγραφές" → d = 2 (min)
2. **Σχεδίασε κάθε βήμα:**
   - Μην κάνεις skip ενδιάμεσες καταστάσεις
   - Κύκλωσε τα κλειδιά που ανεβαίνουν/κατεβαίνουν
3. **Ελέγχες:**
   - Όλα τα φύλλα στο ίδιο επίπεδο; ✓
   - Όλοι οι κόμβοι (εκτός ρίζας) έχουν $\ge d$ κλειδιά; ✓
   - Τα κλειδιά τηρούν τη σειρά; ✓

### 4.3 Checklist Πριν την Απάντηση

- [ ] Υπολόγισα σωστά το $d$ (min occupation)?
- [ ] Έκανα Copy Up στα φύλλα (και όχι Push Up)?
- [ ] Έκανα Push Up στους εσωτερικούς (και όχι Copy Up)?
- [ ] Ενημέρωσα τους next pointers στα φύλλα?
- [ ] Έλεγξα αν η ρίζα χρειάζεται split/merge?

## 5. Συχνές Παγίδες (Common Pitfalls)

❌ **ΛΑΘΟΣ:** "Διαγράφω κλειδί από φύλλο, άρα το διαγράφω και από τον γονέα"
✅ **ΣΩΣΤΟ:** Οι τιμές στους γονείς είναι separators. Μπορεί να μείνουν ακόμα και αν δεν υπάρχουν στα φύλλα.

❌ **ΛΑΘΟΣ:** "Κάνω push up το κλειδί από φύλλο"
✅ **ΣΩΣΤΟ:** COPY UP από φύλλο (το κλειδί μένει ΚΑΙ ανεβαίνει)

❌ **ΛΑΘΟΣ:** "Redistribution πάντα από αριστερό αδελφό"
✅ **ΣΩΣΤΟ:** Μπορείς από οποιονδήποτε γείτονα (δεξί ή αριστερό) που έχει περίσσεια

❌ **ΛΑΘΟΣ:** "Όλοι οι κόμβοι έχουν ακριβώς $d$ κλειδιά"
✅ **ΣΩΣΤΟ:** Κάθε κόμβος έχει $[d, 2d]$ κλειδιά (range, όχι σταθερό)

## 6. Πρόσθετα Θέματα

### 6.1 B+ Tree vs B Tree

| Χαρακτηριστικό | B+ Tree | B Tree |
|----------------|---------|--------|
| Δεδομένα σε φύλλα | ✓ Μόνο στα φύλλα | ✗ Σε όλους τους κόμβους |
| Sequential scan | ✓ Γρήγορο (linked list) | ✗ Αργό (tree traversal) |
| Fan-out | ✓ Υψηλότερο | ✗ Χαμηλότερο |
| Range queries | ✓ Πολύ γρήγορο | ✗ Αργό |

### 6.2 Variants

- **B*-Tree:** Min occupation 2/3 αντί για 1/2
- **Prefix B+ Tree:** Συμπίεση κλειδιών (compression)
- **Bulk Loading:** Δημιουργία από ταξινομημένα δεδομένα (bottom-up)

## 7. Σύνοψη Τύπων

```
Κόστος Search: d(I) όπου d(I) = ⌈log_{d}(n)⌉

Χωρητικότητα κόμβου:
  - Min: d κλειδιά (εκτός ρίζας: 1)
  - Max: 2d κλειδιά

Fan-out: Με n κλειδιά → n+1 δείκτες

Ύψος δέντρου με N κλειδιά:
  h ≤ ⌈log_{d+1}(N)⌉
```
